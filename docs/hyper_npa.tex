\begin{abstract}
Neural Particle Automata (NPA) encode images and shapes as local particle
dynamics. HyperNPA asks whether a single feed-forward model can map an input
image to an NPA instance whose rollout reconstructs the condition. This revision
updates the paper around the current end-to-end training path: image
\(\rightarrow\) DINO ViT-S full-token condition \(\rightarrow\)
token-aware rectified-flow LoRA generator \(\rightarrow\) shared-base NPA rollout.
The shared NPA base and the conditioned LoRA generator are trained jointly from
step zero with a rollout image loss, rather than training per-sample adapters and
regressing to their raw factor coordinates.

The current 10k OmniSVG run is functional but not at oracle parity. It trains on
9500 examples and holds out 500, uses online DINO features, CUDA/Burn autodiff,
rank-16 generated LoRA, 128-particle four-step training rollouts, and TBPTT
chunks of two steps. The selected checkpoint reaches 8.56 dB mean target-image
PSNR over 32 holdout validation samples at the training-scale rollout setting;
the best validation sample reaches 16.75 dB and the worst reaches 0.56 dB. New
paper figures include actual \texttt{bevy\_gaussian\_splatting} render captures
of eight held-out image-conditioned HyperNPA rollouts at 2048 particles across
steps 4, 16, 64, and 128. These renders show that feed-forward inference works,
but also that long-rollout stability and image fidelity remain weak.

For context, the strongest oracle-trained NPA comparison remains an exact
adapter-bank control, not the current E2E model: direct exact LoRA materializes
persisted oracle NPAs at 99 dB, and a deterministic DINO-flow zero-source
control reaches 30.44 dB mean / 27.31 dB minimum render PSNR over 16
2048-particle oracle samples. The current learned E2E HyperNPA has not achieved
the 26 dB oracle-parity gate. The main remaining work is therefore not
visualization plumbing; it is raising E2E dynamics quality and validating it
against matched high-particle oracle NPAs.
\end{abstract}

\section{Claim Boundary}

This document reports the current local \texttt{burn\_automata} HyperNPA state.
The term HyperNPA refers to an image-conditioned generator of NPA weights or
adapters, followed by particle rollout. The current default inference artifact
is:

\begin{itemize}[leftmargin=*]
  \item artifact directory:
  \path{artifacts/hyper2d_e2e_rollout_train_omnisvg_10k_steps3000_b16_p128s4_rank16_cosine_cuda}
  \item shared NPA base: \path{shared_base.bpk}
  \item HyperNPA generator: \path{hyper_2d.json}
  \item DINO checkpoint: \path{models/dino/dino_vits.mpk}
\end{itemize}

The current result is not a proof of broad 1k/10k generalized oracle-quality
image \(\rightarrow\) NPA generation. What is proven is narrower:

\begin{enumerate}[leftmargin=*]
  \item the E2E image-conditioned inference path loads a condition image, runs
  DINO, emits a generated LoRA adapter, installs it on the shared NPA base, and
  rolls out in the Bevy/WGPU viewer;
  \item the 10k training run improves the target-image rollout objective from a
  broken initial state to a measurable but low-fidelity holdout solution;
  \item separate exact-oracle adapter-bank controls show that the NPA plus LoRA
  representation can match per-sample oracle NPAs when the adapter is correct;
  \item the current learned E2E model is still far below the oracle comparison
  threshold and lacks matched high-particle oracle validation on its 10k holdout
  slice.
\end{enumerate}

\section{Current Architecture}

The current 2D HyperNPA pipeline is trained directly against rollout image loss:
\[
\begin{aligned}
\text{image} &\rightarrow \text{DINO full-token grid}
\rightarrow \text{conditioned rectified-flow LoRA} \\
&\rightarrow \text{shared-base NPA rollout}
\rightarrow \text{target image loss}.
\end{aligned}
\]

\paragraph{Condition encoder.}
Each condition image is resized to 518 pixels and encoded with DINO ViT-S/14.
The model uses the CLS token plus the full \(37\times37\) patch-token grid:
1370 tokens with 384 dimensions, or 526080 flattened values before the
token-aware pooling path. The training run used online DINO and batch size 16.

\paragraph{Hypernetwork.}
The generator is token-aware and rectified-flow inspired. It consumes condition
tokens, a sampled source state, and a short two-step flow sampler, then emits a
rank-16, \(\alpha=16\) LoRA adapter vector for the NPA MLP. The report labels
this conditioner as \texttt{token\_attention\_pool\_rectified\_flow\_generated\_lora}
with four token-attention heads, hidden width 128, and generated output dimension
5586.

\paragraph{Shared NPA base.}
The base model is a growing-2D NPA initialized from the upstream seed. Unlike the
older two-stage adapter-bank experiments, the shared NPA base is trainable from
step zero together with the generator. This better matches the intended use
case: the shared dynamics should learn reusable particle communication and
growth behavior, while the condition-specific adapter steers the rollout.

\paragraph{Training objective.}
The selected 10k run optimizes a target-2D rollout image objective, not raw
adapter-vector MSE. It uses 128 rollout particles, four rollout steps, update
probability 0.5, 64-pixel target loss images, 512 target samples, splat loss
weight 2.0, color loss weight 5.0, density loss weight 1.0, and boundary /
overflow regularization. TBPTT chunks of two steps bound the training graph. The
training backend is Burn/CUDA autodiff with dense pair interactions capped by
the configured chunk sizes.

\section{Interpretation}

The current training paradigm is better aligned with the intended HyperNPA use
case than the older raw-adapter regression path. It avoids a separate
per-sample LoRA optimization loop and trains the shared base plus conditioned
adapter generator directly through the downstream rollout image objective.
However, this does not automatically solve the quality problem.

The evidence now separates three levels:

\begin{enumerate}[leftmargin=*]
  \item \textbf{Representation upper bound.} Exact adapters and the
  zero-source DINO-flow control can match oracle NPAs at high particle count.
  \item \textbf{Current learned E2E model.} The online image-conditioned model
  learns a real signal on 10k examples, but only at low rollout scale and with
  low target-image PSNR.
  \item \textbf{Renderer integration.} The Bevy/WGPU path can run feed-forward
  HyperNPA inference from an image and render 2048-particle Gaussian splats, but
  visual rollouts are not yet stable enough for an oracle-quality claim.
\end{enumerate}

The most important negative result is long-horizon stability. In
Figure~\ref{fig:e2e-bevy-rollouts}, several top validation samples produce
visible early particle structure but collapse to sparse or near-empty renders by
step 64 or 128. This indicates that the training horizon, stability losses, and
quality-scale validation must be strengthened before the model can be presented
as a high-quality image-to-NPA generator.

\section{Remaining Work}

\begin{enumerate}[leftmargin=*]
  \item Generate matched high-particle oracle NPAs for the E2E validation slice
  and report HyperNPA-vs-oracle PSNR for the same images shown in
  Figure~\ref{fig:e2e-bevy-rollouts}.
  \item Train with longer rollout horizons and a curriculum that reaches at
  least 2048-particle validation without dense all-pairs memory blowups.
  \item Add stability objectives that penalize collapse, off-frame drift, and
  late-rollout extinction.
  \item Compare trainable shared-base E2E training against a frozen-base E2E
  variant and a direct per-sample oracle baseline on identical samples.
  \item Improve throughput by replacing dense quality-scale backward passes with
  tiled or sparse GPU kernels, then re-run the 10k experiment with longer
  rollouts and larger validation batches.
  \item Continue to use Bevy headless exports for paper figures so the paper
  reflects the actual viewer/inference stack.
\end{enumerate}

\section{Conclusion}

HyperNPA has moved from adapter-vector reconstruction toward the more appropriate
end-to-end image conditioned training paradigm: DINO tokens feed a generated LoRA
adapter, the adapter modulates a shared trainable NPA, and the whole path is
optimized through rollout image loss. The current 10k run proves this path is
implemented and learning, and the new Bevy figures prove feed-forward image
input to rendered NPA rollout works. It does not yet prove oracle-quality
generalization. The oracle-trained NPA controls show that the representation can
reach the target quality band; the learned E2E model now needs to close that gap
under matched high-particle validation.
