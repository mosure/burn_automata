\begin{abstract}
Neural Particle Automata (NPA) can compactly encode local particle dynamics, but target-specific training does not by itself produce a general image-to-dynamics model. We study a staged HyperNPA pipeline: an image condition is encoded with DINO ViT-S token-grid features, a rectified-flow generator emits a LoRA adapter vector, and the adapter modulates a shared NPA base. This revision replaces earlier low-particle and sparse visual evidence with 2048-particle oracle comparisons over 16 OmniSVG validation targets and high-particle rollout panels.

The strongest current result is an overfit control, not a broad generalization result. Direct exact LoRA adapters reproduce persisted per-sample oracle NPA models at 99 dB render PSNR. A deterministic zero-source DINO-token-grid rectified-flow control overfits the same 16-sample adapter bank with adapter-vector normalized RMSE \(1.18\times10^{-7}\), cosine 1.0, and 2048-particle render PSNR mean/min of 30.44/27.31 dB against the oracle baseline. The WGPU-trained rectified-flow model on the same target fails badly, with vector normalized RMSE 1.112, cosine 0.151, and render PSNR mean/min of 9.10/0.53 dB. Thus the representation and validation path can express high-quality adapters, but the current WGPU flow optimizer/objective has not yet learned them, and generalized DINO/flow HyperNPA quality is not established.
\end{abstract}

\section{Scope and Claims}

This paper is a status report for the local \texttt{burn\_automata} HyperNPA experiments. It separates four objects that were previously conflated:

\begin{enumerate}[leftmargin=*]
  \item an independently overfit per-sample oracle NPA;
  \item a stored direct LoRA adapter materialized on a shared NPA base;
  \item a deterministic DINO-conditioned rectified-flow control that exactly constructs adapter vectors;
  \item a WGPU-trained DINO-conditioned rectified-flow hypernetwork.
\end{enumerate}

Only the first three currently pass the narrow 16-sample overfit validation. The fourth is the model class we ultimately care about, and it currently fails. No result in this document should be read as proof of broad 1k/10k generalized image-to-NPA quality.

\section{Architecture}

The intended 2D HyperNPA pipeline is:
\[
\text{image} \rightarrow \text{DINO token grid} \rightarrow
\text{rectified-flow LoRA generator} \rightarrow
\text{shared-base NPA rollout}.
\]

The shared base is a 2D growing NPA. For each sample, an adapter supplies low-rank deltas to the NPA MLP layers:
\[
\Delta W_\ell = \frac{\alpha}{r} A_\ell B_\ell.
\]
The current exact-oracle experiments use rank \(r=132\), \(\alpha=132\), and 45,172 adapter parameters per sample. The condition encoder stores an 8-by-8 DINO ViT-S token-grid descriptor. The flow generator is trained or constructed to map the condition to an adapter vector.

\paragraph{Rectified-flow adapter generator.}
The desired learned generator receives condition features, timestep \(t\), and a noisy adapter state \(z_t\), then predicts adapter velocity. The sampled adapter is integrated over fixed steps. The control model in this paper sets source noise to zero and constructs a condition interpolator in closed form; it proves the inference path and adapter representation can express the targets. It does not prove that gradient training finds the solution.

\section{Validation Protocol}

The current paper-quality gate uses:

\begin{itemize}[leftmargin=*]
  \item 2048 rollout particles;
  \item 32 rollout steps;
  \item 128-by-128 Gaussian raster metrics;
  \item render sigma 1.0 px;
  \item update probability 0.5;
  \item seed 42 and uniform-circle initialization;
  \item direct, generated, and oracle BPKs materialized for the same samples.
\end{itemize}

The PSNR metric compares generated rollouts to persisted per-sample oracle NPA rollouts, not to the original image thumbnails. Direct exact adapters are expected to reach 99 dB because they are constructed from the same oracle model weights; this is a materialization sanity check. HyperNPA adapters are compared against the same oracle rollouts.

\subsection{Historical Pilot Results}

The older 10k OmniSVG shared-base run remains useful only as a representation pilot. It used 64 rollout particles and 8 rollout steps, with 9000 train and 1000 holdout adapters. Its sampled low-count oracle comparison had train/holdout mean ratios 1.079/1.075 and max ratios 1.141/1.126. Those numbers suggest that a shared base plus per-sample adapters is plausible, but they do not meet the current high-particle evidence standard.

The older 1k summary-token condition-to-LoRA generator also remains a negative baseline. It covered 900 train and 100 holdout examples, but vector normalized RMSE was 0.979 on train and 1.016 on holdout, with mean cosine 0.194 and 0.053. This failure motivated the DINO token-grid and rectified-flow path.

\section{Interpretation}

The main conclusion changed from the earlier paper draft. We can now say:

\begin{itemize}[leftmargin=*]
  \item The exact adapter representation is sufficient to materialize oracle NPAs.
  \item DINO token-grid conditions are available and can key an exact condition-to-adapter interpolator on a 16-sample slice.
  \item The rectified-flow sampling path can emit adapter vectors with near-zero error when constructed correctly.
  \item The current WGPU-trained rectified-flow model does not learn the same mapping.
  \item Therefore the remaining bottleneck is the learned flow objective/optimizer/architecture, not the PSNR gate, DINO cache plumbing, or adapter application path.
\end{itemize}

This is a meaningful course correction: the project now has a clean overfit target and a high-particle oracle gate. It still lacks proof of broad 1k/10k generalization from image condition to DINO to rectified-flow LoRA to NPA.

\section{Next Work}

\begin{enumerate}[leftmargin=*]
  \item Replace the WGPU rectified-flow objective with a formulation that can match the zero-source control on the 16-sample exact bank.
  \item Add holdout exact-oracle samples and require a split gate, not train-only overfit.
  \item Scale the exact bank from 16 to 128 and 1k samples while keeping the 2048-particle PSNR gate.
  \item Reintroduce nonzero flow source noise only after deterministic zero-source training passes.
  \item Generate WGPU/Bevy Gaussian screenshots for direct, HyperNPA, and oracle models once the generated models are visually meaningful under the same high-particle rollout settings.
  \item Move from exact interpolator controls to a real DINO-conditioned flow network with validation-set model selection.
\end{enumerate}

\section{Limitations}

The passing result is train-only and has 16 samples. It does not establish holdout generalization, 1k/10k behavior, or visual parity with image-space targets. The direct exact LoRA baseline is intentionally trivial because it materializes oracle weights. The DINO-flow zero-source model is also a control, because it is constructed by a host-side solve. The WGPU-learned model remains the decisive failing path. Finally, the current paper panels are dense particle rollout visualizations; polished image-like output still requires better target training, rendering losses, or downstream Gaussian rendering.

\section{Conclusion}

HyperNPA remains a plausible route to image-conditioned particle automata, but the evidence is now narrower and cleaner. The repo has a high-particle oracle gate, an exact adapter baseline, a DINO-conditioned rectified-flow control that passes 26 dB on 16 samples, and a matched WGPU training failure. The next paper-worthy claim requires turning that control into a learned WGPU model and then proving holdout and scale behavior under the same 2048-particle oracle comparison.
